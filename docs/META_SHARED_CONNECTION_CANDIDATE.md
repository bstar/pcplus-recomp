# Shared Meta connection-test package

The reviewed candidate now includes all15 public application files, including
matched PCLINE.OVL and PCMETA.OVL companions. Its tracked recipe and a2644-file
public-source export reproduce every file and the deterministic ZIP exactly.
[The receipt](validation/meta-shared-connection-candidate.json) binds identities,
six DOS package workflows and31 package-contract cases. This is software
acceptance for a connection-test candidate, not physical acceptance or complete
original feature parity.

The packager requires agreement among Meta feature flags, module descriptor,
actual parent loader header, CRC/fixup layout, verified memory layout and payload
hash. A shared runtime also requires its Line/Port companion and Meta frontend.
The archive requires declared companions and rejects missing, modified or
undeclared files before creating its output. CRC/hash checks identify matched
bytes; they are not an authentication mechanism for untrusted manifests.

Seventeen Meta cases include refusal of forged payload hashes, wrong fixup
counts, mismatched runtime declarations and incomplete archives/recipes.
Fourteen Line/Port control cases still pass. Rebuilding the preceding14-file
recipe produces its unchanged archive, so existing candidate recipes retain
their byte identities.

Actual DOS8086 workflows exercise packaged START/SETUP, the original magenta
splash with the LoC annotation, native Alt-P, Alt-M with the sibling Meta module,
Chat/contextual Help and DOS-side source compilation followed by ASPECT
DATE/TIME/ALARM/EMULATE execution. All six synthetic PRM/DIR/KEY/KBD/XLT/FON
sentinels remain unchanged; launchers restore the environment and hardware.
The precompile case also omits the selected BIOS COM entry.

Parent/interpreter/module hashes match the earlier capacity, UI, fault,
carrier/reconnect and actual Enigma/SynthModem transfer checkpoints. Those
receipts retain their original scope, including386/UMB for observed ASPECT
carrier diagnostics and8086 for the ordinary capacity/protocol cases.

Build with the pinned Nix wrapper:

```sh
./tools/build-connection-candidate \
  --recipe standalone/meta_shared_connection_candidate_recipe.json \
  --output-dir build/my-meta-connection-candidate
```

The output contains `package/PCPLUS` and `archive/PCPLUSSE.ZIP`. Building does not
select or deploy it. Local selection, verified deployment/rollback and physical
observations belong in the private machine record. Keep the package together
and preserve existing settings, dialing files and call history during updates.
