# Shared client checks restore EMULATE capacity

The combined EMULATE parent/interpreter now passes the stream and nested-child
workflows that failed in the initial binding checkpoint. Sharing repeated client
checks and completion code saves 208 bytes from the interpreter without reducing
buffers, streams, numeric banks, stacks or heap policy. The new pair is accepted
for these capacity workflows; release and physical acceptance remain open.

The [validation record](validation/aspect-emulate-shared.json) binds the sources,
model comparisons, actual DOS results, cold rebuild and historical negative
receipt. It records `capacity_accepted: true` and `release_accepted: false`.

## Preserved request behavior

Only the optional EMULATE profile shares these operations:

- Attachment/client/PROGRAM validation retains its original position relative
  to each method's owner and operand checks. Short-circuit behavior is retained.
- The four identical serial-ready prefixes retain their existing Boolean UART
  check. The stricter `active == 1` checks in other methods stay separate.
- Post-request client/PROGRAM failure overrides the typed parent result; the
  parent result overrides callback error. Required callback acknowledgements
  and policy-cache updates still occur afterward.

Request arguments, callback flags, wait ownership and typed conversion stay in
place. PROGRAM end, snapshot retirement and other operations with different
ownership rules retain their existing paths. The ordinary profiles expand the
original statements and keep their exact executable bytes. The comparison-only
`ASPECT_RENDER_RESPONSE_LEGACY` switch selects those same statements for tests;
it is not selected by the application builder.

## Evidence

Two compiled copies of the actual C client run under DOS8086: one with the
legacy statements, one with shared helpers. All 38,400 cases match. They cover
16 request paths, attached/detached/PROGRAM/window/confirm states, serial values
0/1/2, parent/bridge results, callback errors, injected pre/post client-check
failures, and nested EMULATE attempts during synchronous callbacks. Comparisons
include outcomes, check/request counts, callback traces, policy values and a
subsequent request.

Those bridge, client-check and serial boundaries are explicit models. The
comparison does not prove identical real-stack thresholds or timing. Helper
calls change temporary stack use while retaining the existing stack capacities
and real canary/admission checks. Actual boundary-pressure tests remain required.

Actual DOS with the real VM and bridge separately passes:

- 30 checks on386 with profile changes, six held streams, three DOS children,
  DATE/TIME, missing-file recovery, subsequent scripts and exact view restoration.
- 29 checks on8086 with profile changes and six streams around three DOS children.
- One active ALARM/XOFF/carrier-loss case on ANSI6, with a verified high-memory
  observer: typed error, speaker/duration cleanup, registration retirement,
  DS=SS, JFT/sink restoration and parent command-menu return.

Both capacity profiles observe VT220 and ANSI DA replies twice, generated by the
actual parent parser after script EMULATE commands. The peer sends only queries
and ACK strings. The specialized screen check expects the reset view plus ACK6;
it does not require the deliberately cleared old banner to remain.

A clean export of 5,456 public files reproduces parent and interpreter exactly.
It repeats 306 linked parent-owner checks, all device/word/buffer comparison
suites, the 38,400-case client comparison and the386 held-stream/profile workflow.
It contains no originals, private configuration, prior objects or Git ancestry.
The root8086 and ALARM cases are not repeated by that cold proof.

Fresh non-EMULATE controls remain exactly `b4f0aecc` and `91256a7b`. Installed
R59A85A8 and its settings/call history are unchanged.

selectors, modal/WHEN/native-error and fatal-reset paths. Measure receive service
during keyboard import and screen reset. Repeat Enigma/Synchronet regressions
and package reproduction on these exact products before selection, then test the
physical Boca/SPA2102/SynthModem path. The wider original-feature inventory stays
open. This checkpoint is not a deployment or full-parity claim.
