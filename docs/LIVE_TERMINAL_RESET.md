# Current-profile RIS

The live executable implements ESC c for its supported VT220 (4) and ANSI (6) profiles as a maintained reset policy. It restores the configured startup emulation in RAM, clears the screen, and homes the cursor. This is deliberately separate from the exact native `20a4` reconstruction documented in [TERMINAL_RESET.md](TERMINAL_RESET.md): native nonzero reset calls an unrecovered KEY/profile file-loading pipeline and broader application UI services. No native reset blob or unresolved profile-loader shortcut is linked here.

`terminal_reset_capture` must run after validated configuration, keyboard detection/import, mode-3 initialization, tab initialization and startup clear/home, before UART enable. It captures explicitly named terminal state, the entire 948-byte (79-slot) keymap and 30-byte tab table. It returns AX=0 for profiles 4/6 and AX=1 otherwise. RIS before a successful capture takes the explicit unsupported-service20a4 cleanup path. The capture is source-owned RAM, not a serialized original memory image.

`ansi_escape_service_20a4` and `csi_reset_terminal` restore that startup state. Their near ABI preserves BP, SI, DI and ES and leaves any caller-owned cdecl argument on the stack. They reset parser parameters, character sets, mode flags, DECSC state, attributes, wrap, scroll/origin margins, geometry, cursor and protection/viewport gates. The keymap is restored verbatim, including imported binary bytes: DECCKM changes cannot permanently replace an explicit startup KBD mapping. The native DECCKM rewrite-enable gate also returns to its captured startup value; it is not a separate current application-cursor-mode latch. They clear all owned attribute, attribute-value, shadow and line-flag storage using known source-owned symbols, then call the actual recovered clear/home and restore the BIOS cursor shape.

The reset performs no DOS or file IO. Connection/modem state, UART hardware and flow control, RX/TX queues, CLI/typed configuration, keyboard BIOS selection, translation configuration, sink handles and history remain owned by their existing services. RIS does not redial, reload a profile, discard pending transmission or replace user configuration. Capturing again is an explicit application action, not something the incoming parser performs.

Run `./tools/dev --command python3 standalone/check_terminal_reset_live.py` after building the live executable. The checker executes the actual linked services, real UART receive path, ESC parser, recovered video clear and cursor helpers. Only hardware interfaces are modeled. It tests both profiles, dirty margins/protection/pointers, all metadata storage, a binary explicit KBD baseline, DECCKM, parser continuation, caller registers and preservation of transport/application state. Native exact-byte/original comparisons belong to the separate native diagnostic; they do not assert byte equivalence for this policy.

The ignored result is `build/terminal/terminal-reset-live-checks.json`. This is CPU execution with hardware models; actual DOS reset/transport checks are separate integration evidence.
