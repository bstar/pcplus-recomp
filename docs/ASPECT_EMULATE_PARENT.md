# Experimental EMULATE parent transaction

The parent profile transaction now executes the existing keyboard staging,
configuration application and clean reset code for maintained profiles4/6.
**It is unaccepted:** adding the owner increases the parent minimum by256 bytes,
and the held-stream/nested-child DOS test fails seven of27 checks. Memory funding
is required before enabling the command. The child RPC and VM opcode are still
unbound; the installed release is unchanged.

[The receipt](validation/aspect-emulate-parent.json) deliberately records
`passed: false`, alongside separate passing component and source-rebuild results.
The experimental parent is `c5e5ba00`; the ordinary control is exactly `689bdce9`.

## Parent-owned behavior

`--aspect-emulate-policy` links `terminal_script_emulate` in the existing ASPECT
code bank. The option requires the current ALARM/snapshot parent profile; it
publishes no new renderer capability or child entry. The far function accepts
an AX selector and returns a typed ASPECT result, preserving the other registers
and FLAGS. Its two small resident adapters use the existing near stage/finish
functions. The ordinary build omits this component's code.

The owner rejects non-byte selectors with operand7 and unimplemented profiles
with unsupported3. For supported4/6 requests, it checks pending staging, windows,
confirmation, editor/browser and quit owners, then executes the actual renderer
admission policy. This requires a coherent view and script foreground state.
No UART, IRQ, rate, connection-controller or modem setting is acquired or changed.

Keyboard import completes before live configuration changes. Explicit KBD uses
the previously bound canonical path and strict reader; default maps use the
existing caller-owned948-byte staging area. Import failures return I/O5 and
retain live profile, map and screen. A successful stage applies the new profile
through the existing full clean reset, installs the staged map and captures the
new RIS baseline. Even a same-profile request resets the view. Successful calls
restore the prior setup status; a fatal commit/reset failure retains the existing
finish routine's orderly-exit request and returns state10 rather than success.
That fatal commit branch still requires fault-injection acceptance.

A DOS close error makes the keyboard handle's lifetime uncertain. The strict
reader does not export that handle identity. This owner therefore retains a
quarantine and rejects subsequent supported requests with state10 until PCPlus
process restart, without another import. Tests cover a close error alone and a
primary seek error followed by a close error. This protects the new script path;
it does not repair every existing caller of the shared reader.

The transaction reuses the existing staging buffers. Near data/stacks remain
65,504 bytes. Resident code grows eight bytes to65,460; the ASPECT code bank grows
240 bytes. The minimum including PSP rises from479,680 to479,936 bytes. No stack,
stream, numeric, serial or screen capacity is reduced.

## Observations and open gates

The actual linked owner passes294 CPU cases through modeled BIOS/DOS/UART
boundaries. No product function is substituted. Cases cover repeated and
same-profile switches, default/explicit maps, all unsupported byte selectors,
non-byte requests,16 owner guards, open/seek/read/close/short/invalid/unbound
imports, recovery after known import failures, close quarantine, and subsequent
parent DA replies/RIS. The fixture seeds script-owner state; it does not establish
an actual child lease. Screen checks use the24-row terminal area in the current
25-row status layout.

A5,443-file public-source export reproduces the experimental parent exactly and
repeats all294 linked cases without originals, private configuration, prior
objects or Git ancestry. A fresh ordinary build retains the installed parent's
exact bytes. These checks do not establish DOS child/RPC scheduling or receive
latency during synchronous file reads and screen clearing.

The separate real-DOS capacity run uses the normal `b4f0aecc` interpreter, six
held streams, local DATE/TIME values and three nested DOS children. It fails
`four_calls`, `all_six_streams`, `first_file`, `six_files`,
`actual_parent_clock_queries`, `three_nested_children`, and
`exact_viewport_cells`. The other20 checks pass. A fresh ordinary-parent control repeats all27 checks
successfully with the same interpreter and harness. This result is retained as an
unaccepted candidate, not hidden by the passing component matrix.
