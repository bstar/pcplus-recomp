# VT52 sub-mode (opt-in, 2026-11-25)

PCPlus 2.01 lets a host switch an ANSI-family session into VT52 mode with
DECANM (`ESC[?2l`) and back with `ESC <`. Some host software still probes for
it, and VT52 is part of the original terminal feature set. The opt-in
`--vt52` build flag (`TERMINAL_VT52`, requires `--ansi-profiles`) restores the
original parser.

Without the flag every object is unchanged. The default minimal (`e25e0bd7…`),
minimal `--ansi-profiles --dec-graphics` (`bee295fe…` at the time, now
`c162ea2d…` with ids 8..11 admitted) and qualified
(`7f5b3b03…`) parents still rebuild byte-identically.

## Recovered code

`reconstruction/vt52/` holds exact source for the two original routines:

| File | Original | Bytes | Role |
| --- | --- | --- | --- |
| `parser.asm` | overlay 14 `f02e..f12c` | 254 | ESC dispatch for terminal id 1 (native thunk `b98b`), with its 34-entry `<`..`]` jump table |
| `cursor.asm` | resident `1f70..1fa0` | 48 | `ESC Y row col`, clamped unsigned to `csi_last_row`/`screen_last_column` |

`recover.py` is an explicit analyst step. It assembles both units flat at
their original addresses, compares them with the verified original executable
and writes `provenance.json` with hashes and file offsets. The build never runs
it and reads no original input.

The recovered command set:

| Sequence | Action |
| --- | --- |
| `ESC A` / `B` / `C` / `D` | cursor up / down / right / left (A–C clear wrap-pending) |
| `ESC F` / `G` | G0 graphics on / off (the same DEC graphics map as ANSI) |
| `ESC H` | home |
| `ESC I` | reverse index |
| `ESC J` / `K` | erase to end of screen / line |
| `ESC L` | clear screen (PCPlus extension) |
| `ESC Y r c` | direct cursor address |
| `ESC Z` | identify: replies `ESC / Z` (original DS `755e`) |
| `ESC V` / `ESC ]` | print cursor line / print screen |
| `ESC W` | printer controller (ends on `ESC X` for profile 1) |
| `ESC <` | return to the previous profile with a clearing reset |
| anything else in `<`..`]`, or below `<` / above `]` | ignored (byte consumed) |

`ESC =`/`ESC >` (keypad modes) are ignored by the original and stay ignored.

## Maintained binding

Near `_TEXT` has only 100–350 bytes free in every parent. The parser therefore
links in a far `VT52_CODE` segment (592 bytes). `src/terminal/vt52_live.asm`
contains:

- **Near entry stubs.** `terminal_escape_b98b` replaces the
  `csi_unimplemented` stub in `boundaries.asm`, and `terminal_profile_switch_reset`
  is the second entry. With the two `call bx; retf` trampolines, these use 19
  near bytes.
- **Far stubs.** These take each native service the recovered code calls
  through a trampoline (`ansi_next_byte`, cursor moves, `screen_set_cursor`,
  reverse index, erase-after, clear screen).
- **Print services.**
  - `ESC V` calls `terminal_screen_print(3)`.
  - `ESC ]` makes the same selection that `csi_media_copy` makes.
  - `ESC W` calls `terminal_controller_run`.
- **Identify.** It sends `ESC / Z` byte by byte. DGROUP is full, so the
  string cannot live there.
- **Runtime profile-switch reset.**
  - The maintained RIS restores the configured snapshot, including the
    terminal id. As a result DECANM, `ESC <` and the SCO id-2 switch were
    previously only a RIS.
  - The wrapper keeps the id the caller selected and rebuilds the per-id
    flags exactly as native `reset.asm` L_20c0..L_2114 does: doublewidth
    1..11, DEC keys 2..11, monochrome 6..7.
  - An id that cannot run here keeps the configured snapshot. Under the flag,
    `reconstruction/modes/core.asm` (DECANM) and `reconstruction/ansi/dispatch.asm`
    (SCO switch) call this wrapper instead of `csi_reset_terminal`.
- **VT52 cursor keys.**
  - On entry to id 1, exact `ESC [ x` / `ESC O x` keymap entries become
    `ESC A..D` and `ESC P..S`. These are the DEC VT52 key codes. Leaving
    VT52 restores the snapshot keymap.
  - This follows the VT52 standard. The original loads a per-id keyboard
    file; that file's VT52 table has not been recovered.

Runtime gates that check the running `csi_terminal_id` now use
`active_profile_gate` / `TERMINAL_ACTIVE_PROFILE_UNSUPPORTED`. These admit 1
only under `TERMINAL_VT52`:

- `viewport_live.asm`;
- `reset_live.asm`;
- `status_transition.c`;
- `row_geometry.c`.

The bank builders pass the flag. VT52 display state equals VT100's. Configured
profiles still use the configuration gate, so id 1 cannot be configured.
`status_transition.c`'s reviewed size-profile hash was refreshed; its code is
unchanged without the flag.

## Actual DOS evidence

`standalone/test_vt52_dos.py` runs in DOSBox-X with an 8086 CPU, no FPU, an
actual COM1 UART and a synthetic modem peer.

**Switch case.**

1. After a typed byte, the peer sends `ESC[?2l` and a VT52 screen ending in
   `ESC Z`.
2. The terminal must reply `ESC / Z`. The typed Up key must reach the wire as
   `ESC A`.
3. On that key, the peer sends `ESC <`, ANSI CUP, primary DA and CPR.
4. The terminal must answer with the configured profile's DA and `1;27R`.
5. The next Up key must be the ANSI one (`ESC [A`).
6. The screen must show only the post-reset text.

**Stay case (`--stay`).** The terminal stays in VT52, and the test checks the
drawn rows:

- home/erase;
- `ESC F lqqk ESC G` drawn as `┌──┐`;
- `ABC ESC D ESC D X` → `AXC`;
- `ESC[1m` printed literally as `1mBOLD`, because VT52 does not interpret CSI;
- EL and cursor up;
- the `ESC Y` clamp to the last row and column 79;
- `ESC A` sent for both Up keys, with no ANSI DA.

| Parent | Profiles (switch and stay) |
| --- | --- |
| minimal `--ansi-profiles --dec-graphics --vt52` `ec560806` | 2, 4, 6 |
| full qualified flag set + all three flags `70d35bef` | 2, 4, 6 |

- **Clamp row.** The minimal parent has 25 terminal rows and clamps to row 24.
  The full parent keeps its status row separate and clamps to row 23.
- **ANSI regression.** The full parent also passes the ANSI-profile case for
  profile 5.
- **Full parent size.** `_TEXT` is 0xfeda, and DS/SS is 65520.

Results are in `build/vt52-dos/`.

## Open

- The status line keeps the configured profile label while in VT52. Native
  label behaviour in VT52 mode has not been checked.
- The original VT52 keyboard table has not been recovered (see above).
- TTY (id 0) still ignores ESC, as in the original. Ids 12+ need their own
  parsers. Ids 8..11 are now admitted ANSI-family profiles
  (`ANSI_FAMILY_PROFILES.md`). The full `--vt52` parent `f82fcb05` passes
  the switch case from id 9 and the stay case from id 11.
- No physical terminal, modem or host acceptance.
